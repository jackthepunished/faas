# ADR-127 · H2C bridge hardening follow-on (G19.1)

- **Status:** proposed
- **Date:** 2026-08-23
- **Issue / PR:** G19.1 (per spec §17) — close the four production-readiness gaps surfaced by the 12-layer audit of PR #1050 (ADR-126 / G19).
- **Related:** ADR-126 (bridge-side H2C terminator, merged 2026-08-23 as `a16e9a744`),
  ADR-124 (per-app `app_protocol` knob), ADR-005 (snapshots are cache, not truth;
  `LazyResnapshot` and `MarkAllSnapshotsStaleByFCVersion`), ADR-016 (additive wire
  changes), ADR-028 (vmmd-stream-bridge inner-leg amendment rollback),
  ADR-070 (gatewayd-public edge h2 listener shape), issue #470 (warm-snapshot
  audit kind), PR C of issue #470 (`emitWarmSnapshotStale` helper).

## Context

PR #1050 (G19 / ADR-126) shipped the bridge-side H2C terminator on 2026-08-23.
The wire-shape follow-on closed the gap from PR #1023 (ADR-124): a customer
with `app_protocol ∈ {http2, grpc}` now reaches their guest's `:8080` as
native H2 frames and native gRPC trailers. `app_protocol=http1` rides the
unchanged H1+chunked path (zero behavior change).

A 12-layer production-readiness audit was run the same day. **Verdict:
not-production-ready for Scale-tier.** Hobby-tier load-bearing core (layers
2/3/5) is OK; Pro OK at expected load; Scale BLOCKED on five layers.

### Audit verdict

| # | Layer | Status |
|---|---|---|
| 1 | Customer-facing surface (CLI + dashboard) | ⚠️ CLI ✅ / Dashboard ❌ |
| 2 | Gateway → vmmd edge | ✅ |
| 3 | vmmd-side forwarder | ✅ |
| 4 | Bridge binary | ⚠️ correctness ✅ / DoS knobs ❌ |
| 5 | Guest-side listener opt-in | ✅ (opaque-502 on non-H2C runners) |
| **6** | **Snapshot invalidation + rollout** | **❌ BLOCKING** — no `FAAS_BASE_IMAGE_VERSION` const, no runbook, no auto-detect |
| **7** | **Observability + dashboards** | **❌ BLOCKING** — zero metrics, zero bridge slog, zero dashboards |
| 8 | Billing correctness | ✅ |
| **9** | **Security** | **❌ BLOCKING** — unbounded listener, unbounded transport, no `recover()` |
| 10 | Rollback safety | ✅ (wholesale `v1` lacks e2e test — covered by G19.2) |
| **11** | **Docs + customer discovery** | **❌ BLOCKING** — `docs/customer/` doesn't exist, §4.1 narrative drift, no runbook |
| 12 | Metal acceptance | ❌ BLOCKING — all 5 metal tests `t.Skip` (deferred to G19.2 / G19.3 follow-ons) |

This ADR closes four of the five blocking gaps (layers 6, 7, 9, 11). Layer 12
(metal acceptance) is deferred to two follow-on issues (G19.2 un-stub the
existing `t.Skip`s; G19.3 add the `metal-h2c-acceptance` Ansible role) so the
shippable surface stays reviewable in ~10 min per commit per CLAUDE.md.

### What this ADR is NOT

- It is **not** a rewrite of the bridge binary. The wire-shape PR #1050 is the
  final bridge behavior; this ADR hardens what is already shipped.
- It is **not** a migration. The `apps.app_protocol` column + `apps_app_protocol_chk`
  CHECK constraint already shipped in `migrations/00382_apps_app_protocol.sql`.
  Per ADR-016 the new `FAAS_BASE_IMAGE_VERSION` constant lives in Go source —
  zero SQL footprint.
- It is **not** a behavior change for `app_protocol=http1` apps. They keep
  the unchanged H1+chunked bridge path; the snapshot invalidation sweep
  (Layer 6) only flips rows where `app_protocol ∈ {http2, grpc}`.

## Decision

### D1 (Layer 6) — `FAAS_BASE_IMAGE_VERSION` constant + F3 sweep

Add a top-level constant in `pkg/fcvm` mirroring `Snapshot.FCVersion`:

```go
// FAAS_BASE_IMAGE_VERSION is the per-image-version stamp the
// h2c-capable base rootfs image is published under. Mirrors
// Snapshot.FCVersion (ADR-005) but for the wire-protocol-capable
// base image rather than Firecracker itself.
const FAAS_BASE_IMAGE_VERSION = "v1"
```

Apps adopting `app_protocol ∈ {http2, grpc}` must adopt this version of the
base image (the H2C-capable runner listener is part of the image). Apps
staying on `app_protocol=http1` are unaffected.

Add two new methods to `pkg/state.PgStore`:

- `MarkAllSnapshotsStaleByAppProtocol(ctx, []string) (int64, error)` — bulk
  flip of every non-stale snapshot whose deployment's app's
  `app_protocol ∈ appProtocols`. Mirrors
  `pkg/state/pgstore.go:9739::MarkAllSnapshotsStaleByFCVersion`.
- `MarkSnapshotStaleByAppProtocol(ctx, snapshotID, []string) error` —
  single-row mirror of `pkg/state/pgstore.go:9654::MarkSnapshotStale`;
  returns `ErrNotFound` on no match.

Add an `imaged` F3 sweep step that runs **after** the existing F2
(`MarkFCSnapshotsStale`) and uses the canonical `emitWarmSnapshotStale` audit
helper (issue #470 / PR C). The F3 block sits at the tail of `runFCSweep` and
returns `true` on partial success so F2's success is preserved even if F3
fails. F3 emits `warm_snapshot_stale` audit kind with
`subject="app_protocol:"+fcvm.FAAS_BASE_IMAGE_VERSION`.

### D2 (Layer 9) — security pins on listener + transports + recover

**Inbound listener hardeners** at `cmd/vmmd-stream-bridge/main.go`:

```go
srv := &http.Server{
    Handler:           newHandler(guestIP, uint16(port), deadline),
    ReadHeaderTimeout: 10 * time.Second,
    MaxHeaderBytes:    api.DefaultMaxHeaderBytes, // 1 MiB (limits.go:3383)
    IdleTimeout:       120 * time.Second,
    ReadTimeout:       30 * time.Second,
    WriteTimeout:      0, // streaming (SSE/long-poll/grpc)
}
srv.Protocols = new(http.Protocols)
srv.Protocols.SetHTTP1(true)
srv.Protocols.SetUnencryptedHTTP2(true)
if h2c, ok := srv.Protocols.Get("h2"); ok {
    if s2, ok := h2c.(*http2.Server); ok {
        s2.MaxConcurrentStreams = 100  // matches gatewayd-public cap
        s2.MaxFrameSize         = 1 << 20
        s2.MaxHeaderListSize    = 1 << 20
        s2.IdleTimeout          = 60 * time.Second
        s2.ReadTimeout          = 30 * time.Second
    }
}
```

`WriteTimeout: 0` preserves streaming semantics for SSE, long-poll, and gRPC
server-streaming. `MaxHeaderBytes` reuses the platform-wide constant
`api.DefaultMaxHeaderBytes` (`pkg/api/limits.go:3383`) — no new platform
constant.

**Outbound H2C client transport pins** on all three H2C transports
(`newGuestH2CTransport` in `cmd/vmmd-stream-bridge/h2c_terminator.go`,
`newStreamBridgeH2CTransport` and `newInternalProxyH2CTransport` in
`pkg/vmmdgrpc/forward.go`):

```go
const h2cMaxFrameSize         = 1 << 20       // 1 MiB
const h2cMaxHeaderListSize    = 1 << 20       // 1 MiB
const h2cMaxConcurrentStreams = 100           // matches gatewayd-public cap
const h2cStreamReceiveWindow  = 512 * 1024    // 512 KiB (stdlib default)
```

`MaxConcurrentStreams` on `*http2.Transport` is the **requested** value
emitted in the client's SETTINGS frame; the real per-conn cap is what the
server responds with. The transport field is set so SETTINGS is well-formed
on the wire; the server-side cap lands on the inbound `http.Server` above.

**Panic recovery + transport cleanup** in `handleH2CStream`:

```go
defer func() {
    if rec := recover(); rec != nil {
        http.Error(w, fmt.Sprintf("bridge panic: %v", rec), http.StatusInternalServerError)
        slog.Error("vmmd-stream-bridge: handleH2CStream panic", ...)
    }
}()
transport := newGuestH2CTransport(guestIP, guestPort)
defer transport.CloseIdleConnections()
```

A panic in any downstream call no longer crashes the bridge; the stdlib H2C
server would itself log the panic but does NOT close the conn — the client
sees a hang. The `defer recover()` translates panic → 500 + close, then
keeps serving. `defer CloseIdleConnections` releases the guest TCP fd even
if `RoundTrip` returned early.

### D3 (Layer 7) — observability

**Per-request framing-selection slog line** at `newHandler`:

```go
slog.Info("vmmd-stream-bridge: framing selected",
    "framing", framing.String(),
    "app_protocol_env", os.Getenv("FAAS_BRIDGE_PROTOCOL"),
    "guest", net.JoinHostPort(guestIP, strconv.FormatUint(uint64(guestPort), 10)),
    "method", r.Method,
    "path", r.URL.Path,
)
```

Logged at `Info` (not `Debug`) because the `FAAS_BRIDGE_PROTOCOL` env flip
is the operator's primary rollback signal — they need to see every request's
framing decision. Mirrors the gatewayd-side line at
`pkg/gateway/forwardproxy.go:321`; promoted to `Info` here because the
bridge is the closer-to-the-metal hop.

**New counter** in `pkg/wire/metrics.go`:

```
vmmd_bridge_framing_total{app_protocol, bridge_protocol, framing}
```

Labels: `app_protocol ∈ {http1, http2, grpc}` (from `pkg/api/app_protocol.go`),
`bridge_protocol ∈ {h1, h2c}`, `framing ∈ {match, mismatch}` where
`mismatch` means `bridge_protocol` ≠ `appProtocolToBridgeProtocol(app_protocol)`
— the operator-forced surgical-rollback signal. Pre-instantiate the closed
cross-product (3 × 2 × 2 = **12 series**) at boot.

**New Prometheus alert** in `pkg/api/alerts.go`:

```yaml
alert: FaasBridgeFramingMismatch
expr: sum by (app_protocol, bridge_protocol) (
          rate(vmmd_bridge_framing_total{framing="mismatch"}[5m])
       ) > 0.1
for: 1h
severity: warning
```

The mismatch row is the operator's primary signal that a customer is being
downgraded on the wire without their consent. Runbook: `docs/ops/h2c-rollback.md`.

**New Grafana dashboard** `deploy/grafana/bridge-protection.json` (uid
`bridge-protection`, tags `["bridge", "h2c", "g19"]`). Four panels:

1. Bridge framing rate by (app_protocol, bridge_protocol) / 5m — timeseries.
2. Bridge framing MISMATCH rate / 5m (alert source) — timeseries.
3. Active bridge_protocol=h1 (surgical-rollback apps) — stat, orange threshold 1.
4. Bridge H2C handshake latency p99 — timeseries (drop the panel if the vmmd-side
   `op="bridge_h2c_roundtrip"` histogram doesn't exist by PR time).

## Consequences

- **Operator visibility on the framing decision.** `bridge_framing_total` +
  `FaasBridgeFramingMismatch` + `bridge-protection` dashboard + per-request
  slog line together close Layer 7. Operators no longer have to guess whether
  the surgical rollback is firing.
- **No more listener DoS surface.** `MaxHeaderBytes = 1 MiB` caps request
  header size. `MaxConcurrentStreams = 100` caps concurrent streams per
  conn. `MaxFrameSize = 1 MiB` caps per-frame memory.
- **No more panic-induced conn hang.** `defer recover()` translates panic →
  500 + close; `defer CloseIdleConnections` releases the guest TCP fd even
  on early return.
- **Bounded cold-boot spike on image bump.** F3 sweep flips only
  `app_protocol ∈ {http2, grpc}` snapshots, mirroring the opt-in scoping in
  ADR-126 §Decision 6. `app_protocol=http1` snapshots stay valid forever.
- **No migration footprint.** Wire-additive per ADR-016. The
  `apps.app_protocol` column + CHECK constraint already shipped in
  `migrations/00382_apps_app_protocol.sql`. The F3 sweep operates on existing
  tables.
- **Out of scope stays out of scope.** Layer 12 (metal acceptance) is
  closed via G19.2 + G19.3 follow-on issues; not bundled into this PR.

## Rejected alternatives

- **All five layers in one PR.** Rejected because Layer 12 (metal acceptance)
  requires the `metalAvailable(t)` gating + a new Ansible role + a fixture
  set — a separate ~2000 LOC + 1-2 days of bare-metal x86_64 validation per
  CLAUDE.md §14. Bundling layers 6/7/9/11/12 into one PR exceeds the
  reviewable-in-~10-min budget per CLAUDE.md.
- **OpenAPI / SDK regen for the new `FAAS_BASE_IMAGE_VERSION`.** Rejected:
  `FAAS_BASE_IMAGE_VERSION` is an internal Go constant — never crosses the
  customer API surface. The wire-protocol customer knob is `apps.app_protocol`,
  already shipped via PR #1023 (ADR-124).
- **Wire-additive proto bump for the new metric label set.** Rejected:
  Prometheus label sets are not part of any wire contract; they're scraped
  from `/metrics` HTTP endpoint which is unauthenticated and consumer-decode.
- **Replace F2 + F3 with a single combined sweep.** Rejected: F2 runs on
  Firecracker-version mismatch (ADR-005 contract); F3 runs on app-protocol
  mismatch (this ADR). Different triggers, different audit subjects. Merging
  them muddies the `warm_snapshot_stale` audit kind's `subject` field.

## Out of scope (filed as future ADRs)

- **Layer 12 — metal acceptance** (G19.2 + G19.3 above; opened as
  follow-on issues from commit 12).
- **Per-app ALPN preference at the cert engine.** `gatewayd-public` ALPN h2
  stays universal. Per-app ALPN is a customer-runtime concern (their cert
  choice), not a platform knob. (Carried over from ADR-126 §"Out of scope".)
- **One-bridge-stream-per-guest-conn → conn-multiplexed.** Today's shape is
  one dial per H2C stream. A future ADR might multiplex across N streams on
  a single guest conn if dial latency becomes the bottleneck.
- **Guest-side HPACK header table tuning.** Defaults via
  `golang.org/x/net/http2.Transport` are good enough; profile-driven tuning
  is a separate concern.
- **gRPC-web support.** gRPC-web is HTTP/1.1 + trailers; the bridge's h1
  fallback already handles it.
- **HTTP/2 connection migration (RFC 8441).** Connection migration would
  enable cross-host failover of long-lived streaming RPCs.
- **HTTP/3 + QUIC** — issue #680, deferred until http2 is in fleet.
- **ADR-046 per-instance egress metering** — issue #415, interacts with
  per-stream byte accounting for h2 streams.
