# ADR-055 · Per-host egress policy templating

- **Status:** proposed
- **Superseded (in part, PR-E):** prose referred to the monolithic
  `cmd/gatewayd/` daemon split by ADR-070 into `gatewayd-public` (TLS-only
  edge) and `gatewayd-internal` (routing + wake + proxy). Body is preserved
  verbatim; readers should substitute "gatewayd-internal" for the
  routing/wake/proxy path and "gatewayd-public" for the certmagic/TLS path.
  `cmd/gatewayd/<file>.go` citations in this body are stale; see PR-E for
  the new file locations.
- **Date:** 2026-07-31
- **Issue:** #95 slice 5 (multi-box rollout, Tier 1 Phase 4)
- **Decision:** Replace the static `policy_nftables.conf` artifact
  with a Jinja2 template that substitutes `public_iface` and
  `masquerade_cidr` per host, and add a runtime `pg_notify` watcher
  in `cmd/vmmd` so future policy changes can roll without an
  `ansible` rerun. The Go renderer in `pkg/netns.HostPolicy.Render()`
  remains the single source of truth for the ruleset body; the
  Jinja2 layer is a per-host verifier, not a parallel writer.

## Why

The reference default-local node ships with `eth0` and a `10.100.0.0/16`
tenant bridge. A compute node on a different NIC name
(typically `ens5` or `enp0s3`) cannot use the existing
`deploy/ansible/roles/nftables/files/policy_nftables.conf` artifact
— the file hard-codes `iifname "br-tenants" oifname "eth0" accept`
and `ip saddr 10.100.0.0/16 oifname "eth0" masquerade`, so a
multi-box deployment would either:

1. Reuse the wrong NIC name (tenant traffic forwarded to a
   non-existent interface — every wake returns `ENETUNREACH`).
2. Ship a different `.conf` file per host (breaks the single-source-
   of-truth contract; the Go renderer parity-check in
   `make egress-render` would disagree with the deployed file).

Today, the only escape hatch is a manual `make egress-render` against
a draft file checked into the role — a process that doesn't scale
and that bypasses the §11 security contract gate.

This ADR commits to:

1. **Per-host variables enter via ansible `host_vars`**. The
   `nftables` role's `defaults/main.yml` exposes `public_iface`
   (default `"eth0"`, matching `pkg/netns.DefaultHostPolicy`) and
   `masquerade_cidr` (default `"10.100.0.0/16"`, same source).
   `host_vars[<compute_node>].public_iface` overrides the default
   for non-default-local nodes.

2. **`policy_nftables.conf.j2` is the per-host template**. The
   Jinja2 substitutions happen at exactly two sites
   (the forward chain's `iifname … oifname … accept` rule and the
   postrouting chain's `ip saddr <cidr> oifname … masquerade`
   rule). The template body is byte-identical to the current
   static file for the default values, so `make egress-render`
   regression parity holds.

3. **The Go renderer is the source of truth**. `cmd/faas-nft-render`
   gains `--public-iface` and `--masquerade-cidr` CLI flags plus
   `FAAS_PUBLIC_IFACE` / `FAAS_MASQUERADE_CIDR` env fallbacks. The
   `make egress-render` artifact is the Go render; the Jinja2 render
   is verified against the Go render at every CI run via a new
   `egress-render-cross-check` target. They must be byte-identical
   for the default values, and they must agree on the substitution
   sites for non-default values.

4. **A runtime watcher in `cmd/vmmd` rolls the policy without a
   manual `ansible` rerun**. A new pg_notify channel
   `egress_policy_changed` fires when an operator updates an
   `egress_policy` audit row (the source of truth for "what's
   deployed right now"). The watcher consumes the notification,
   re-renders the policy with the current `PublicIface`, writes a
   staging file, validates via `nft -c -f <staging>`, atomic-replaces
   `/etc/nftables.conf`, and reloads via `nft -f`. Mirror
   `cmd/gatewayd/nodecache.go::WatchEvictions` and
   `pkg/sched/nodekeys.go::Run` drain-loop patterns. Gated on
   `cfg.ComputeNode.NodeName != ""` so single-box daemons don't
   observe the channel.

## Cross-check contract (load-bearing)

The Jinja2 template is **a verifier, not a parallel writer**. The
Go render is committed for every default value; the Jinja2 render
is regenerated by ansible at `make bootstrap` time and the two
MUST be byte-identical:

- The `make egress-render-cross-check` target diffs the Go render
  against the Jinja2 render for the default values. Failure is a
  CI red. A future renderer change that adds a new nft token must
  be mirrored in the Jinja2 template before merge.
- The two substitution sites (`{{ public_iface }}` and
  `{{ masquerade_cidr }}`) are pinned individually in
  `pkg/netns/policy_test.go` (single-field tests) so the Go
  side's substitution logic can't silently regress to a
  hard-coded default.

## Out of scope

- **Cross-host policy sync** (every node picks up the same
  `egress_policy` row via the `pg_notify` channel). The watcher
  is per-host; the canonical state is the Postgres row, not a node
  local cache. A future slice adds a fan-out if multi-tenancy
  demands it.
- **Policy diff visualisation** (tell the operator what changed
  before they approve a deploy). Today's CI gate is byte-equality;
  a future slice adds a `egress-policy-diff` Makefile target.
- **Tiered policy** (one set per tenant plan). The current model
  is one host-wide ruleset; tiered policies ride on a future
  ADR-057.
- **Policy rollback on `nft -c -f` validation failure**. The
  watcher writes to a staging file, validates, then
  atomic-replaces. If validation fails, the staging file is left
  on disk and the operator is expected to inspect it; a future
  slice adds automatic rollback to the previous good file.

## Rejected alternatives

- **Push the policy from a control plane via cron.** The control
  plane already talks to compute nodes via `pg_notify`; a
  separate cron-shaped push is one more mechanism to maintain.
  The `pg_notify` channel is the load-bearing one for
  `compute_node_changed`; adding `egress_policy_changed` to the
  same channel keeps the operator surface uniform.
- **Skip the watcher; rely on `ansible` rerun.** The watcher
  keeps the policy hot-reloadable for the nomad case where an
  operator needs to roll a new public IP range without a full
  `make bootstrap`. Single-box installations don't observe the
  channel (the gate is `cfg.ComputeNode.NodeName != ""`), so the
  cost is one goroutine + one DB connection per compute node.
- **Make `policy_nftables.conf` a templated text body in
  `pkg/netns`.** The render is already in Go; templating
  `nftables.conf` inside Go would require inventing a new
  templating engine (text/template, html/template) and breaks
  the `make egress-render` parity check. The Jinja2 path keeps
  ansible idiomatic.
- **Render the policy from the `pg_notify` payload directly.**
  The watcher re-renders via `pkg/netns.HostPolicy.Render()`,
  not from the payload. The payload is just a "wake up; the
  audit row changed" event; the canonical values still live in
  `pkg/netns.DefaultHostPolicy` + `host_vars`. This avoids the
  watcher carrying a separate copy of the policy.
